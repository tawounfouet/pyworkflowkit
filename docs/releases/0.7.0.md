# PyWorkflowKit 0.7.0

Release date: 2026-09-27

## Capability

PyWorkflowKit 0.7.0 stabilizes the compatibility surface of the embedded workflow
runtime.

The line closes M41 through M46 without adding a new scheduler, daemon, worker fleet,
web control plane, RBAC system, or business-specific workload model.

Its purpose is to make compatibility explicit, versioned, documented, testable, and
release-qualified before ecosystem interoperability work begins in 0.8.

## Highlights

- executable package-root public API freeze;
- lifecycle enum and RuntimeEvent vocabulary freeze;
- MetadataStore and UnitOfWork contract freeze;
- explicit deprecation policy and warning categories;
- CLI machine contract v1;
- stable CLI command, exit-code, JSON-key and handled-error expectations;
- Plugin API v1 ecosystem contract;
- reusable third-party plugin compatibility diagnostics;
- immutable published Alembic migration history;
- persistence schema contract v1;
- historical SQLite and PostgreSQL upgrade qualification;
- explicit rejection of unknown/future database revisions;
- artifact-oriented Release Qualification workflow;
- wheel installation qualification on Python 3.11, 3.12, and 3.13;
- sdist installation qualification;
- reference-contract, migration and security release gates.

## Compatibility contract

0.7.0 establishes the following stable-intent boundaries:

~~~text
package-root Python API
workflow/task/attempt lifecycle vocabularies
RuntimeEvent taxonomy
CLI machine contract v1
RunManifest schema v1
Plugin API v1
MetadataStore / UnitOfWork
Persistence Schema Contract v1
Alembic migration lineage
Release Qualification Contract v1
~~~

Compatibility additions may evolve these surfaces only according to the documented
deprecation and version-transition policy.

## CLI machine contract

Automation-facing CLI behavior is explicitly qualified.

Stable expectations include:

~~~text
commands
application exit codes
JSON required keys
handled-error JSON shape
stdout / stderr ownership
version output
manifest JSON delegation to RunManifest schema v1
~~~

Consumers should ignore unknown additive JSON keys.

## Plugin ecosystem contract

Plugin API v1 freezes:

~~~text
executor
metadata
workload
event
~~~

and their entry-point groups.

Third-party packages can validate registrations using the same compatibility contract
used by runtime discovery.

Discovery remains metadata-first and opt-in. M44/M47-style ecosystem work does not imply
automatic plugin execution.

## Persistence compatibility

The published migration history is:

~~~text
0001_runtime_metadata
        ↓
0002_task_output_checkpoints
        ↓
0003_retry_eligible_at
~~~

These published migration files are immutable history.

Future schema changes must append new revisions rather than edit 0001-0003 in place.

0.7.0 qualifies historical data upgrades from 0001 and 0002 to the current head on both
SQLite and PostgreSQL.

## Security baseline

The release preserves:

~~~text
shell=False subprocess execution
subprocess environment isolation by default
observability redaction
secret-aware configuration handling
Bandit
pip-audit
detect-secrets
Dependency Review integration
~~~

This is a hardened trusted-code runtime. It does not claim adversarial plugin or Python
handler sandboxing.

## Stable 0.7 boundary

0.7.0 deliberately does not add:

~~~text
scheduler
background daemon
distributed coordinator
worker fleet
web UI
RBAC / IAM
multi-tenant control plane
business connector catalog
AI agent semantics
exactly-once execution claims
~~~

These remain external, plugin-owned, workload-specific, or Ochestrix responsibilities.

## 1.0 blockers status

The original 1.0 blockers were:

~~~text
unstable public API
undocumented compatibility break
missing migration policy
missing security baseline
missing release automation
~~~

0.7 materially addresses each of these through M41-M46.

They remain subject to further ecosystem pressure in 0.8 and release-candidate review in
0.9 before the final 1.0 contract freeze.
