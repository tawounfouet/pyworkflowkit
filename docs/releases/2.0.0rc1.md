# PyWorkflowKit 2.0.0rc1

PyWorkflowKit 2.0.0rc1 is the release-candidate freeze for the V2 architecture.

This candidate introduces no new post-beta orchestration capability. It promotes the
already-qualified V2 contracts to the package root, freezes compatibility-critical
states/identities/protocols, and composes LOT-00 through LOT-21 into one auditable
release-evidence manifest.

## Breaking root API

The package root now exposes the canonical V2 surface:

```text
ExecutionPlan
PyWorkflowKitError
RetryPolicy
TaskAttempt
TaskAttemptId
TaskDefinition
TaskRun
TaskRunId
TimeoutPolicy
WorkflowDefinition
WorkflowResult
WorkflowRun
WorkflowRunId
WorkflowRuntime
__version__
```

The historical 1.x public-api snapshot remains available as migration evidence, but it no
longer describes the current 2.0 package root.

Legacy capabilities remain available from their historical qualified modules where
applicable. V1-to-V2 semantic migration tooling remains under
`pyworkflowkit._compat.v1_to_v2`.

## Frozen V2 contracts

The RC evidence manifest freezes and composes:

- architecture and root API;
- authoring and deterministic planning;
- workflow/task/attempt states;
- runtime identity and result boundaries;
- retry/backoff and timeout semantics;
- Executor and MetadataStore protocols;
- strict boundary wire contracts;
- V2 plugin compatibility;
- PyIngestKit and PyTransformKit anti-corruption boundaries;
- V1 migration posture.

The stable execution identities are:

```text
CorrelationId
WorkflowRunId
TaskRunId
TaskAttemptId
```

## Complete qualification

LOT-22 requires the complete qualification matrix:

- Python 3.11 / 3.12 / 3.13;
- Ruff, format and strict mypy;
- DAG/planning and state-machine acceptance;
- retry, timeout and cancellation;
- executor and metadata-store conformance;
- SQLite/PostgreSQL recovery and migration paths;
- reconciliation fault scenarios;
- serialization golden fixtures;
- plugins and optional-dependency isolation;
- security gates;
- sibling adapter conformance;
- wheel and sdist installation;
- Customer 360;
- V1 migration fixtures;
- docs/examples;
- deterministic release-evidence manifest.

## RC change policy

After this candidate is qualified:

```text
architecture redesign: forbidden
new feature scope: forbidden
contract reshaping: requires RC reset
blocker fixes: permitted
```

Stable `2.0.0` promotion is LOT-23 and requires a complete re-run of the qualification
matrix with only RC blocker fixes applied.
