# PyWorkflowKit 0.8.0a3

Development milestone: M49 — Observability Interoperability

## Capability

0.8.0a3 adds a vendor-neutral telemetry projection layer on top of committed
RuntimeEvents.

Durable runtime events remain the source of truth; telemetry is an isolated secondary
projection.

## Added

- `OBSERVABILITY_INTEROPERABILITY_CONTRACT_VERSION = "1"`;
- `TelemetryCorrelation`;
- `TelemetryEvent`;
- `TelemetryMetric`;
- `TelemetryMetricKind`;
- `TelemetryProjection`;
- `TelemetryBackend`;
- `RuntimeTelemetryProjector`;
- `RuntimeTelemetrySink`;
- dependency-free `OpenTelemetryBackend` using injected tracer/meter objects;
- M49 unit and reference acceptance coverage.

## Correlation

Telemetry events preserve:

~~~text
event_id
run_id
task_run_id
task_id
attempt_number
event_sequence
~~~

These remain PyWorkflowKit identities and are not replaced by trace/span identifiers.

## Generic metrics

M49 introduces:

~~~text
pyworkflowkit.runtime.events
pyworkflowkit.workflow.started
pyworkflowkit.workflow.completed
pyworkflowkit.workflow.duration
pyworkflowkit.task.started
pyworkflowkit.task.retries
pyworkflowkit.task.completed
pyworkflowkit.task.duration
~~~

Runtime IDs are intentionally excluded from metric labels to avoid high-cardinality
series.

## Redaction and isolation

Telemetry continues through the existing post-commit `ObservabilityDispatcher`.

Sensitive event payload keys remain redacted.

Backend failures remain isolated through `ObservabilityDispatchFailure` and cannot
change workflow state or outcome.

## OpenTelemetry

The reference adapter does not add an OpenTelemetry package dependency.

Applications may inject real OpenTelemetry tracer and meter objects when they already
use that ecosystem.

## Persistence

No schema change and no new Alembic revision.

The migration head remains:

~~~text
0003_retry_eligible_at
~~~
