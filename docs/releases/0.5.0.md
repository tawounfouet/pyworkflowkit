# PyWorkflowKit 0.5.0

Release date: 2026-09-26

## Capability

PyWorkflowKit 0.5.0 delivers a hardened extensible runtime with multiple execution
strategies and production-oriented controls.

This release closes milestones M32 through M36 on top of the concurrent runtime
qualified in 0.4.0.

## Highlights

- `ProcessExecutor` with explicit process transport and hard per-handle termination.
- `AsyncExecutor` with a dedicated asyncio loop, native awaitable execution, and
  cooperative cancellation.
- `SubprocessExecutor` with explicit argv, `shell=False`, captured evidence, hard
  timeout/cancellation, and security policy enforcement.
- `SubprocessSecurityPolicy` with executable, cwd, environment, stdin, stdout, and
  stderr guardrails.
- Parent environment isolation by default for subprocess execution.
- `RuntimeEventSink` observability plugins receiving only committed runtime events.
- `ObservabilitySecurityPolicy` with recursive sensitive-key redaction and default
  sink-error-message redaction.
- Dedicated security CI gates for Bandit, pip-audit, and detect-secrets.
- Pull-request Dependency Review integration, with full enforcement when GitHub
  Dependency Graph is enabled.

## Executor family

The 0.5.0 execution family is explicitly capability-driven:

```text
LocalExecutor
    parallelism  = false
    timeout      = none
    cancellation = none
    async        = false

ThreadExecutor
    parallelism  = true
    timeout      = soft
    cancellation = none
    async        = false

ProcessExecutor
    parallelism  = true
    timeout      = hard
    cancellation = hard
    async        = false

AsyncExecutor
    parallelism  = true
    timeout      = soft
    cancellation = cooperative
    async        = true

SubprocessExecutor
    parallelism  = true
    timeout      = hard
    cancellation = hard
    async        = false
```

Executor workers still do not own runtime state transitions. ConcurrentRunner remains the
coordinator for WorkflowRun, TaskRun, and TaskAttempt lifecycle changes.

## Contract freeze

0.5.0 intentionally preserves the existing durable and public boundary contracts:

- RunManifest schema version remains `1`;
- Plugin API version remains `1`;
- runtime event taxonomy remains unchanged;
- metadata persistence schema remains compatible with the existing Alembic baseline;
- the package-root public API remains intentionally small;
- advanced executor adapters remain explicit module imports;
- retry authority remains RetryPolicy + RetryEngine;
- timeout remains a failed attempt with explicit timeout evidence rather than a new
  runtime status;
- scheduling, RBAC, worker-cluster ownership, and control-plane responsibilities remain
  outside the core.

## Security model

0.5.0 hardens execution boundaries without claiming sandboxing.

Trusted Python handlers and installed plugins execute with the privileges of their
hosting process unless external isolation is provided.

ProcessExecutor provides process isolation but is not an adversarial sandbox.

SubprocessExecutor provides:

```text
shell=False
explicit argv
environment isolation by default
optional executable allowlist
optional cwd-root allowlist
optional environment-key allowlist
I/O boundary limits
```

It does not provide CPU/RAM/network quotas, namespaces, seccomp, container isolation, or
safe execution of arbitrary untrusted code.

## Observability model

The durable event stream remains authoritative:

```text
runtime transition
      ↓
UnitOfWork commit
      ↓
durable RuntimeEvent
      ↓
ObservabilitySecurityPolicy
      ↓
redacted projection
      ↓
RuntimeEventSink
```

Sink failure never rolls back committed runtime state or changes the workflow result.

## Qualification

The 0.5.0 release gate requires:

- Ruff lint and format checks;
- strict mypy over `src`;
- pytest with branch coverage >= 90%;
- Python 3.11, 3.12, and 3.13 matrices;
- transverse executor-capability freeze;
- package-root public API freeze;
- manifest schema version freeze;
- Plugin API version freeze;
- all M32-M36 reference acceptance scenarios;
- wheel build and isolated installation smoke;
- exact package / public `__version__` / CLI version consistency at `0.5.0`;
- migration resources present in the installed wheel;
- PostgreSQL persistence and migration contracts;
- Bandit;
- pip-audit;
- detect-secrets;
- Dependency Review integration.

## Known limitations

0.5.0 does not provide:

- crash recovery;
- stale-run reconciliation;
- resume semantics;
- non-blocking retry scheduling;
- scheduler ownership;
- distributed worker infrastructure;
- operating-system sandboxing;
- RBAC/IAM;
- a secret-management platform;
- web control plane.

These remain deliberate boundaries or later roadmap items.
