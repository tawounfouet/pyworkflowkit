# PyWorkflowKit 0.9.0b1

Developer-experience and documentation stabilization beta.

## Objective

0.9.0b1 implements **RQ-04 — Developer Experience & Documentation**.

The release adds no runtime capability. It proves that the existing public runtime can be
installed, learned, executed, inspected, persisted, and extended without requiring the
internal architecture corpus.

## Added

- Developer Experience Contract v1 targeting `1.0.0`;
- explicit README `Start here` path;
- getting-started, CLI, failure/retry, persistence/evidence, plugin-authoring, and
  troubleshooting guides;
- public failure/retry example;
- public SQLite persistence example;
- public ecosystem-plugin example;
- import-safe decorated workflow for the CLI journey;
- executable source and built-wheel developer-experience qualification gates.

## Changed

- the development line advances from `0.9.0a3` to `0.9.0b1`;
- `examples/00_hello_world.py` now uses only the stable package facade instead of
  constructing internal runner/store/executor components;
- documentation now separates the recommended first-use path from advanced internal
  architecture examples.

## First-use contract

The qualified authoring facades are:

```text
pyworkflowkit
pyworkflowkit.ecosystem
```

The first CLI journey covers:

```text
version
validate
plan
run
inspect
events
manifest
```

## Qualification

RQ-04 executes the same user journey in two environments:

```text
editable source installation
built wheel installation
```

The artifact qualification also verifies both console scripts and cross-process SQLite
inspection.
