# PyWorkflowKit 0.7.0a1

Development milestone: M41 — Compatibility Contract Foundation

## Capability

0.7.0a1 begins the compatibility/stabilization phase.

It deliberately adds no new runtime feature. Instead it converts the core contracts
already proven through 0.1-0.6 into an explicit executable compatibility baseline.

## Frozen baseline

The M41 reference contract records:

~~~text
package-root public API
WorkflowRunStatus values
TaskRunStatus values
TaskAttemptStatus values
RuntimeEventType values
MetadataStore methods
UnitOfWork methods
CLI command names
CLI exit codes
RunManifest schema = 1
Plugin API = 1
migration resources through 0003_retry_eligible_at
~~~

## Why now

The implementation roadmap defines 0.7-0.9 as compatibility/ecosystem/stabilization and
lists unstable public API and undocumented compatibility breaks as 1.0 blockers.

M41 therefore treats compatibility itself as a deliverable.

## Policy

From 0.7 onward, a stable-intent contract change must be visible through:

- compatibility-preserving tests;
- a deprecation path;
- an explicit contract version transition; or
- a narrowly documented security/invariant emergency exception.

Advanced module imports are not automatically promoted to package-root stability.

## Persistence

No migration is introduced.

The migration head remains:

~~~text
0003_retry_eligible_at
~~~

## Runtime

Unchanged:

- lifecycle behavior;
- retry semantics;
- recovery semantics;
- reconciliation semantics;
- executor capabilities;
- RuntimeEvent taxonomy;
- Manifest schema;
- Plugin API;
- scheduler/control-plane boundary.
