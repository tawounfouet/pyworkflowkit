# PyWorkflowKit 2.1.0rc1

> **Status**: Release Candidate 1  
> **Release Target**: PyWorkflowKit 2.1.0  
> **Date**: 2026-10-04  

PyWorkflowKit 2.1.0rc1 is the first release candidate for the 2.1 enterprise series. This release delivers an end-to-end resilient orchestration engine, modern authoring ergonomics, comprehensive OpenTelemetry distributed tracing, full supply-chain security attestations, and a modular CLI with frozen machine contracts.

---

## Highlights of 2.1

### 1. OpenTelemetry Distributed Tracing (LOT-35)
- Standard W3C TraceContext propagation across workflow, task runs, and external workloads.
- Strict isolation of optional OpenTelemetry dependencies (`pyworkflowkit[otel]`) with zero runtime overhead when absent.
- Full span hierarchy: `WorkflowRun` root span parenting `TaskRun` spans, attempt spans, and external workload execution.
- Deterministic trace context injection and extraction across async boundaries and process borders.

### 2. Supply Chain Security & PyPI OIDC Trusted Publishing (LOT-36)
- Passwordless publishing to PyPI via GitHub Actions OpenID Connect (OIDC).
- Cryptographic provenance and signatures generated with Sigstore / Cosign.
- Software Bill of Materials (SBOM) automatically generated in CycloneDX JSON format.
- Automated distribution qualification verifying zero repository leakage (`FORBIDDEN_WHEEL_PREFIXES`, `FORBIDDEN_SDIST_PREFIXES`).

### 3. Modular CLI & Frozen Machine Contract (LOT-31)
- Comprehensive Typer/Rich CLI architecture replacing legacy monolith:
  - `pwk run` : run workflows with interactive Rich rendering or strict `--json` machine output.
  - `pwk plan` : compile and display deterministic execution plans with dependency trees.
  - `pwk inspect` : query historical runs, status, attempts, and checkpoints.
  - `pwk manifest` : extract portable JSON-native run manifests and audit lineage.
  - `pwk doctor` : diagnose execution environment, metadata stores, and optional extras.
  - `pwk store prune` : prune historical workflow runs with retention policies.
- Frozen machine contract snapshot in `contracts/cli_contract_v1.json` with CI parity gates.

### 4. Flow Authoring Ergonomics & Fluid Operators (LOT-32)
- Natural dependency declaration using `>>` and `<<` operators:
  ```python
  task_a >> task_b >> [task_c, task_d] >> task_e
  ```
- Transparent composition with `@task` and `@workflow` decorators.
- Automatic cycle detection at authoring time.

### 5. Selective Resume & Recovery Reconciliation (LOT-33)
- Selective resumption of failed workflows via `runtime.resume_run(run_id, from_task_ids=...)` or `pwk run --resume-from`.
- Reuse of successful upstream task outputs without re-execution.
- Deterministic reconciliation of workflow run state and attempt sequences.

### 6. Transactional Metadata Store Pruning (LOT-34)
- Configurable retention policies (`days_to_keep`, `max_runs_per_workflow`, `dry_run`).
- Atomic cascading prune across workflow runs, task attempts, checkpoints, and event logs.
- Native implementations for both SQLite and PostgreSQL stores.

### 7. Unified Repository & Integration Suite Consolidation
- Clean repository layout with all integration fixtures and test suites consolidated under `integrations/`:
  - `integrations/qualification-integrations/`
  - `integrations/reference-integrations/`
  - `integrations/ecosystem-template/`
  - `integrations/typing-fixtures/`
- Streamlined developer experience aligned with `pytransformkit`.

---

## Upgrade & Compatibility

- **Python Support**: Python 3.11, 3.12, 3.13, 3.14 on Linux, macOS, and Windows.
- **Zero-Breakage Guarantee**: 100% backward compatibility with PyWorkflowKit 2.0.0 and 1.0 historical contracts.
- **Optional Extras**:
  - `pip install pyworkflowkit[otel]` for OpenTelemetry tracing.
  - `pip install pyworkflowkit[postgres]` for PostgreSQL metadata persistence.
  - `pip install pyworkflowkit[dev]` for test and qualification tooling.
