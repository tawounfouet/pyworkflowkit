# PyWorkflowKit 0.9.0rc1

First PyWorkflowKit 1.0 release candidate.

## Objective

0.9.0rc1 implements **RQ-06 — 1.0 Release Qualification**.

The candidate adds no runtime capability. It composes all previously qualified
stabilization evidence into one release-candidate gate.

## Inherited tracks

```text
RQ-01 Public API Freeze                    ✅
RQ-02 Compatibility & Deprecation          ✅
RQ-03 Typing & Static Contracts            ✅
RQ-04 Developer Experience & Documentation ✅
RQ-05 Packaging & Distribution             ✅
```

All five tracks remain contract version `1` and target `1.0.0`.

## Added

- Release-Candidate Contract v1;
- installed-artifact RC qualifier;
- RQ-06 reference acceptance;
- aggregate `1.0 release candidate` job in Release Qualification;
- explicit RC promotion policy;
- explicit manual-publication decision registry.

## Aggregate qualification

The RC gate requires successful qualification of:

```text
artifact installation
public API
compatibility/deprecation
static typing
developer experience
packaging/distribution
contract snapshots
reference integrations
control-plane provider
ecosystem SDK
0.8 interoperability corpus
SQLite upgrades
PostgreSQL upgrades
security
```

It then installs the same built wheel and validates the RQ-06 contract against that
artifact.

## Promotion policy

The candidate freezes:

```text
same-qualified-code-version-metadata-only
```

A direct promotion to `1.0.0` is valid only when no functional code correction is
required after RC qualification.

If a defect requires functional code changes, a later RC must be qualified before 1.0.

## Publication decision

Software license selection remains explicit project/legal work and is not inferred by
the framework or release pipeline.
