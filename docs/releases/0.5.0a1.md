# PyWorkflowKit 0.5.0a1

Development milestone: M32 — ProcessExecutor

## Capability

PyWorkflowKit 0.5.0a1 adds isolated process execution and stronger physical termination
semantics while preserving the 0.4 runtime-state and evidence contracts.

## Added

- `ProcessExecutor` advanced adapter;
- bounded process concurrency;
- explicit process-safe RunContext transport;
- explicit process-safe TaskResult transport;
- serialization preflight for handlers and execution inputs;
- `ExecutorSerializationError`;
- process worker error transfer;
- hard per-handle process termination;
- `TimeoutCapability.HARD`;
- `CancellationCapability.HARD`;
- ConcurrentRunner support for process-backed concurrent executors;
- hard timeout integration through the existing `ExecutionTimeoutError` / RetryEngine
  path;
- hard cancellation integration without introducing new lifecycle states or event types.

## Compatibility

M32 intentionally leaves these 0.4 contracts unchanged:

- package-root API;
- `WorkflowRun`, `TaskRun`, and `TaskAttempt` status enums;
- RuntimeEvent taxonomy;
- RunManifest schema;
- MetadataStore schema and Alembic baseline;
- ThreadExecutor soft-timeout semantics;
- LocalExecutor behavior.

## Process model

For supported Python 3.11-3.13, each active process execution handle owns an isolated
child process inside a bounded active-process set. This enables deterministic per-handle
termination without depending on unavailable per-future termination APIs in the standard
ProcessPoolExecutor on those Python versions.
