# PyWorkflowKit 0.7.0a4

Development milestone: M44 — Plugin Ecosystem Compatibility

## Capability

0.7.0a4 turns the existing plugin compatibility rules into a public, reusable contract
suite for third-party adapter authors.

## Added

- public `validate_plugin_registration()`;
- public `assert_plugin_registration_compatible()`;
- public registration compatibility reports and stable issue codes;
- frozen reverse mapping from entry-point group to PluginType;
- explicit factory-callability validation;
- public `validate_plugin_instance()`;
- public `assert_plugin_instance_compatible()`;
- structural instance checks for Executor, MetadataStore, and RuntimeEventSink;
- third-party conformance documentation and executable reference coverage.

## Discovery

PluginDiscovery now consumes the same public contract suite that external plugin
repositories can call.

Discovery remains metadata-first and opt-in.

## Frozen API-v1 groups

~~~text
pyworkflowkit.executors
pyworkflowkit.metadata
pyworkflowkit.workloads
pyworkflowkit.events
~~~

## Side-effect boundary

Registration validation never invokes the plugin factory.

Instance conformance is an explicit second step controlled by the caller.

## Workload category

No structural workload Protocol is introduced in M44. The category remains the generic
extension boundary already defined by Plugin API v1.

## Runtime impact

No workflow lifecycle, persistence, retry, recovery, manifest, CLI machine-contract, or
migration behavior changes.
