# PyWorkflowKit 2.1.0

> **Status**: qualified stable tag; external publication pending release-remediation closure  
> **Release Candidate**: `2.1.0rc1` (PR #120, commit `63e330b`)  
> **Stable tag commit**: `f5fc4c8a8f258536c0d49e6f11d27ada406c9a61`  
> **Date**: 2026-10-04

PyWorkflowKit 2.1.0 is the qualified stable tag for the 2.1 line. The stable promotion
contains no `src/pyworkflowkit/**` change relative to the qualified RC baseline; the
promotion changed release metadata and release documentation only.

At the time of the post-tag audit, the GitHub Release and PyPI publication were not yet
present. They remain explicit LOT-38 closure gates rather than inferred consequences of
the Git tag.

---

## What's New in 2.1

### 1. OpenTelemetry Distributed Tracing (LOT-35)

- Standard W3C TraceContext propagation across workflow, task runs, and external workloads.
- Optional OpenTelemetry dependency isolation through `pyworkflowkit[otel]`.
- Workflow → task → attempt tracing hierarchy.
- Trace context propagation to supported external workload boundaries.

### 2. Release Automation & Supply-Chain Foundations (LOT-36)

- PyPI Trusted Publishing workflow based on GitHub Actions OIDC.
- CycloneDX SBOM generation.
- GitHub build-provenance attestations.
- Distribution qualification for wheel and sdist artifacts.

These capabilities prepare the trusted-publishing path; they do not by themselves prove
that a specific version has already been published.

### 3. Modular CLI & Frozen Machine Contract (LOT-31)

The frozen top-level machine contract contains exactly nine commands:

- `pwk doctor`
- `pwk events`
- `pwk inspect`
- `pwk manifest`
- `pwk plan`
- `pwk plugins`
- `pwk run`
- `pwk validate`
- `pwk version`

The machine contract is defined by `src/pyworkflowkit/cli_contract.py`.

`pwk store prune` is an additional store-management subcommand and is documented
separately from the frozen nine-command top-level machine contract.

### 4. Customer 360 v2 Reference Pipeline (LOT-37)

- End-to-end reference pipeline with selective resume.
- Transactional pruning and checkpoint reuse.
- Nominal, incident, resume, and upstream-output-reuse acceptance paths.

## Upgrade guidance

PyWorkflowKit 2.1 is designed as an additive, backward-compatible evolution of 2.0.

Once the target release is actually published to PyPI, installation uses:

```bash
pip install pyworkflowkit==<published-2.1.x-version>
```

The exact public version must match the final release decision made after remediation
(`2.1.0` if the existing tag is intentionally repromoted before external distribution,
or `2.1.1` if tag immutability is preserved).
