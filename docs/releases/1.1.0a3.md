# PyWorkflowKit 1.1.0a3

## Developer Experience — DX03

PyWorkflowKit 1.1.0a3 turns `docs/guides/` into the canonical progressive
Zero-to-Hero learning path for the stable embedded workflow runtime.

This alpha introduces no workflow-runtime semantic change.

## Added

- canonical `docs/guides/README.md` learning index;
- 29 numbered guide chapters from `00_ZERO_TO_HERO.md` through
  `27_PRODUCTION_PATTERNS.md`, plus `99_COMPLETE_REFERENCE_APPLICATION.md`;
- progressive coverage of installation, tasks, definitions, dependencies, DAGs,
  planning, runtime execution, RunContext data flow, retries, events, manifests,
  metadata stores, SQLite, PostgreSQL, configuration, CLI operation, concurrency,
  timeout/cancellation, executors, plugins, external workloads, custom adapters,
  control-plane integration, PyIngestKit integration, testing, debugging, and
  production patterns;
- a complete guide-level reference workflow using `fetch → validate → transform → publish`;
- DX03 reference acceptance covering guide topology, chapter progression, public
  beginner imports, canonical `pwk` CLI usage, and legacy-guide redirects.

## Changed

- the repository README now starts the learning journey from `docs/guides/README.md`;
- historical guide paths remain available as compatibility redirects to the canonical
  numbered chapters;
- beginner-facing documentation consistently uses the package-root public API;
- new CLI examples use `pwk` as the canonical command and reserve `--json` for
  machine-facing usage;
- the 1.1 roadmap advances from Rich CLI work to the completed guide architecture.

## Preserved

- the stable 1.0 runtime contracts;
- CLI Machine Contract v1;
- `pyworkflowkit` and `pyworkflow` compatibility aliases;
- the product boundary: PyWorkflowKit remains an embedded workflow runtime, not a
  scheduler or control plane.

## Cross-surface boundary

DX03 explains concepts. It does not prematurely absorb the next roadmap lots:

```text
DX03  guides explain
DX04  .py examples execute
DX05  notebooks explore
DX06  cross-surface qualification proves consistency
```

References to future canonical scripts and notebooks are therefore identified as DX04/DX05
targets until those lots land.
