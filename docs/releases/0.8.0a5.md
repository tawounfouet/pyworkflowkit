# PyWorkflowKit 0.8.0a5

Development milestone: M51 — Control-Plane Provider Contract

## Capability

0.8.0a5 adds a stable, schema-first provider boundary for control planes such as
Ochestrix.

## Added

- `CONTROL_PLANE_PROVIDER_CONTRACT_VERSION = "1"`;
- `ControlPlaneProvider` runtime-checkable protocol;
- `WorkflowRuntimeProvider`;
- stable control-plane operation identifiers;
- portable capability, validation, workflow-inspection, run, lineage, recovery and
  reconciliation schemas;
- `ControlPlaneProviderError` and `ControlPlaneCapabilityError`;
- artifact-level provider conformance qualification.

## Provider operations

~~~text
validate_workflow
inspect_workflow
execute_workflow
inspect_run
list_runtime_events
retrieve_manifest
retrieve_lineage
request_cancellation
assess_recovery
reconcile_run
resume_run
inspect_capabilities
~~~

## Capability truthfulness

The built-in WorkflowRuntime provider advertises:

~~~text
request_cancellation = false
background_execution = false
scheduling_owned_by_control_plane = true
~~~

Calling unsupported cancellation raises `ControlPlaneCapabilityError` rather than
pretending an external cancellation mechanism exists.

## Portable boundary

Workflow definitions cross as `WorkflowDefinitionSchema` or equivalent mappings.

Handlers, executors, MetadataStore instances, RuntimeComponents, ORM rows and sessions do
not cross the boundary.

## Security

- execution parameters are normalized through the strict portable JSON contract;
- run summaries omit raw parameters;
- runtime event payloads are defensively redacted;
- canonical RunManifest redaction remains unchanged.

## Release qualification

A fresh virtual environment installs the built wheel and exercises the provider contract
using only public imports.

The new control-plane provider job is required by the aggregate Release Qualification
gate.

## Persistence

No schema change and no new Alembic revision.

Migration head remains:

~~~text
0003_retry_eligible_at
~~~
