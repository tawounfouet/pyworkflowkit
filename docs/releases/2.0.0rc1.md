# PyWorkflowKit 2.0.0rc1

PyWorkflowKit 2.0.0rc1 is the release candidate for the canonical V2 architecture
implemented by LOT-00 through LOT-22.

## Canonical root

The package root now exposes only the narrow V2 surface frozen by the architecture
baseline:

```text
ExecutionPlan
PyWorkflowKitError
RetryPolicy
TaskAttempt
TaskAttemptId
TaskDefinition
TaskRun
TaskRunId
TimeoutPolicy
WorkflowDefinition
WorkflowResult
WorkflowRun
WorkflowRunId
WorkflowRuntime
__version__
```

The former 1.1 root aliases are not preserved as ambiguous 2.x aliases. Legacy 1.x
contracts remain available through their qualified implementation/migration surfaces.

## V2 contract freeze

The RC freezes:

- canonical public namespace exports;
- WorkflowRun, TaskRun and TaskAttempt state vocabularies;
- WorkflowRunId, TaskRunId, TaskAttemptId and CorrelationId identity categories;
- Executor and CancellableExecutor method contracts;
- MetadataStore method contract;
- V2 portable wire-contract identities and versions;
- PyIngestKit and PyTransformKit integration contract version 1.

The executable baseline lives in:

```text
pyworkflowkit.contracts.v2_release_candidate
tests/reference/test_v2_lot22_release_candidate.py
```

## Migration

LOT-21 migration remains the only V1 → V2 migration authority. It is fail-closed and
does not invent fingerprints, correlation, retryability, reconciliation truth or
ExternalRunRef attempt ownership.

## Release evidence

`scripts/qualify_v2_release_candidate.py` emits a deterministic evidence manifest that
combines:

- the frozen 2.0 RC contract;
- the V1 migration contract;
- SHA-256 fingerprints for V2 wire golden fixtures;
- Customer 360 acceptance fixture evidence;
- migration fixture evidence.

Release Qualification runs this against the built wheel, outside the repository import
path, while reading immutable fixture evidence from the checked-out source.

## Qualification scope

The RC qualification includes:

- Python 3.11 / 3.12 / 3.13;
- Ruff, format and mypy;
- DAG/planning and state-machine tests;
- retry/backoff and timeout/cancellation;
- executor and MetadataStore conformance;
- recovery/reconciliation fault injection;
- wire golden fixtures;
- plugin compatibility;
- security gates;
- PyIngestKit/PyTransformKit sibling conformance;
- optional-dependency isolation;
- wheel and sdist installation;
- Customer 360 beta workflow;
- V1 migration fixtures;
- documentation/examples;
- deterministic release evidence manifest.

## RC change policy

After this candidate is merged, changes to the frozen 2.0 contract require an RC reset
unless they are blocker fixes that preserve the frozen contract. LOT-23 may therefore
apply blocker fixes and release metadata changes, but it must not introduce a new
architecture.
