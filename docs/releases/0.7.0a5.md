# PyWorkflowKit 0.7.0a5

Development milestone: M45 — Persistence & Migration Compatibility

## Capability

0.7.0a5 formalizes the durable relational schema as persistence contract v1 and proves
historical upgrade compatibility.

## Frozen lineage

~~~text
0001_runtime_metadata
  -> 0002_task_output_checkpoints
  -> 0003_retry_eligible_at
~~~

No new migration is introduced by M45.

## Added

- PERSISTENCE_SCHEMA_CONTRACT_VERSION = "1";
- explicit packaged migration history and head constants;
- supported historical upgrade-origin contract;
- rejection of unknown database revisions before migration;
- rejection of unknown explicit upgrade targets;
- MigrationCompatibilityError;
- immutable migration-source fingerprint acceptance tests;
- SQLite historical-data upgrades from 0001 and 0002;
- PostgreSQL historical-data upgrades from 0001 and 0002;
- post-upgrade reads through the current MetadataStore;
- post-upgrade current-version writes through UnitOfWork.

## Historical compatibility

Rows persisted before task output checkpoints or retry eligibility existed remain
readable after migration to the current head.

Historical task attempts naturally acquire:

~~~text
retry_eligible_at = NULL
~~~

which maps to None in the current domain model.

## Upgrade direction

The supported product contract is forward migration to head. Downgrade compatibility is
not promoted to a stable product promise in M45.

## Runtime impact

No workflow execution, state-machine, retry, recovery, CLI, plugin, manifest, or event
semantics change.
