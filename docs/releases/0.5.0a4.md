# PyWorkflowKit 0.5.0a4

Development milestone: M35 — Observability Plugins

## Capability

PyWorkflowKit 0.5.0a4 adds a typed, event-driven observability plugin boundary over
committed RuntimeEvents.

## Added

- RuntimeEventSink protocol;
- ObservabilityDispatcher;
- ObservabilityDispatchFailure diagnostics;
- deterministic sink fan-out;
- post-commit event publication;
- sink failure isolation;
- WorkflowRuntime.register_event_sink();
- WorkflowRuntime.observability_failures;
- typed PluginCatalog.events registry;
- sequential and concurrent runner integration;
- M35 unit and reference acceptance coverage.

## Core invariant

```text
persistent state + RuntimeEvent
        ↓
commit
        ↓
observability sink
```

The order cannot be reversed.

## Failure policy

Observability plugins are best-effort secondary projections.

A sink failure:

- is recorded;
- is logged;
- does not roll back durable state;
- does not alter workflow status;
- does not prevent other sinks from receiving the event.

## Plugin category

The existing plugin category is retained:

```text
PluginType.EVENT
entry point = pyworkflowkit.events
factory type = RuntimeEventSink
```

No new vendor-specific plugin type is introduced.

## Compatibility

M35 leaves unchanged:

- RuntimeEvent taxonomy;
- RuntimeEvent persistence schema;
- MetadataStore contracts;
- lifecycle status enums;
- RunManifest schema;
- executor contracts;
- retry semantics;
- timeout semantics;
- cancellation semantics;
- existing stdlib structured logging.

## Vendor neutrality

0.5.0a4 has no runtime dependency on:

- OpenTelemetry;
- Prometheus;
- Datadog;
- Grafana;
- cloud monitoring SDKs.

Those systems can be supported by external RuntimeEventSink plugins.
