# PyWorkflowKit 0.6.0a2

Development milestone: M38 — Reconciliation

## Capability

0.6.0a2 verifies ambiguous external work identified by M37.

Provider-specific verifiers query external systems through `ExternalRunRef` and return
a normalized external status.

PyWorkflowKit then produces a conservative reconciliation report.

## Normalized statuses

```text
RUNNING
SUCCEEDED
FAILED
CANCELLED
NOT_FOUND
UNKNOWN
```

## Dispositions

```text
CONFIRMED_SUCCEEDED
CONFIRMED_FAILED
CONFIRMED_CANCELLED
STILL_RUNNING
MANUAL_REQUIRED
```

## Conservative ambiguity handling

M38 uses `MANUAL_REQUIRED` when:

- no verifier exists for the provider;
- verification fails;
- the provider returns UNKNOWN or NOT_FOUND;
- multiple external references disagree;
- ambiguous local running work has no external evidence.

## Security boundary

Provider exception messages are not copied into reconciliation evidence.

Only the exception type is retained.

## Persistence

M38 is read-only.

No migration is introduced.

No runtime state transition or recovery event is emitted.

- Plugin API = 1;
