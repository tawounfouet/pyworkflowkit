# PyWorkflowKit 0.7.0a2

Development milestone: M42 — Deprecation Policy & Compatibility Warnings

## Capability

0.7.0a2 adds the controlled-evolution mechanism required by the M41 compatibility
baseline. M42 does not deprecate an existing PyWorkflowKit API.

## Added

- typed API/CLI/configuration/plugin/persistence deprecation categories;
- DeprecationSpec with since/removal/replacement/reason metadata;
- visible FutureWarning-based PyWorkflowKit warning hierarchy;
- once-per-identity DeprecationEmitter;
- caller-oriented warn_deprecated() helper;
- optional deprecated() callable decorator;
- explicit ACTIVE_DEPRECATIONS catalog;
- duplicate-catalog validation;
- minimum removal-window validation;
- documented emergency exception.

## Default window

A normal deprecation may not be removed inside the same minor release line.

~~~text
0.7.x -> earliest normal removal 0.8.x
0.9.x -> earliest normal removal 1.0.x
1.2.x -> earliest normal removal 1.3.x
~~~

## Emergency exception

An earlier target requires emergency=true plus an explicit reason and is reserved for
security or invariant-correctness situations.

## Compatibility

M42 leaves the M41 baseline unchanged: package-root API, lifecycle/event vocabularies,
MetadataStore/UnitOfWork, CLI surface, Manifest schema v1, Plugin API v1, migration head,
and runtime execution/recovery semantics.

## Active deprecations

None.
