# PyWorkflowKit 0.9.0a3

Typing and static-contract stabilization alpha.

## Objective

0.9.0a3 implements **RQ-03 — Typing & Static Contracts**.

The release adds no runtime capability. It qualifies the existing public contracts as
strict external-consumer typing surfaces on the path to 1.0.

## Added

- machine-readable Typing Contract v1 targeting `1.0.0`;
- release qualification of the existing PEP 561 `py.typed` marker;
- strict external-consumer typing fixture;
- negative fixture proving unsupported two-argument task handlers are rejected;
- Python 3.11 / 3.12 / 3.13 static-typing qualification;
- built-wheel typing gate in Release Qualification.

## Fixed

### Declarative task signatures

`@task` previously used a generic `ParamSpec`, allowing static acceptance of handler
signatures that executors cannot invoke.

The annotation is now aligned with the existing `TaskHandler` runtime contract:

```text
() -> object
or
(RunContext) -> object
```

### Ecosystem Protocol support types

Public Ecosystem SDK Protocols previously leaked type dependencies through internal
`domain` and `ports` module paths.

The existing support types required to implement `Executor`, `MetadataStore`,
`UnitOfWork`, and `RuntimeEventSink` are now re-exported through
`pyworkflowkit.ecosystem`.

This is a compatibility repair to an already-public extension contract, not a new runtime
feature.

## Reference integrations

- the reference executor now uses the exact public `TaskDefinition` / `TaskHandler`
  contract;
- the reference event sink imports `RuntimeEvent` through the ecosystem facade;
- the ecosystem template exposes an explicit generic plugin-registration return type.

## Static qualification

A valid public consumer must pass:

```text
mypy --strict
```

for all supported Python targets.

An intentionally invalid two-argument `@task` handler must fail the same check.
