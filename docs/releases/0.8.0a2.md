# PyWorkflowKit 0.8.0a2

Development milestone: M48 — External References & Portable Integration Evidence

## Capability

0.8.0a2 formalizes ArtifactReference and ExternalRunRef as portable ecosystem evidence
without changing their stable 0.7 constructors or introducing artifact storage.

## Added

- `REFERENCE_INTEROPERABILITY_CONTRACT_VERSION = "1"`;
- stable lowercase provider-name validation;
- absolute portable URI validation;
- JSON-portable reference metadata normalization;
- explicit ArtifactReference portability validation;
- explicit ExternalRunRef portability validation;
- `ReferenceInteroperabilityError`;
- M48 unit and durable reference acceptance coverage.

## Compatibility model

Historical 0.7 reference constructors remain unchanged.

M48 portability is an explicit stronger contract applied to integrations that need
cross-runtime or durable evidence guarantees.

## Provider identity

Portable providers use stable lowercase identifiers such as:

~~~text
pyingestkit
acme.jobs
github-actions
vendor_1
~~~

Provider names are never silently normalized.

## Foreign identity

Foreign `external_run_id` values and URIs are preserved exactly through serialization,
persistence, manifest construction and lineage evidence.

## Manifest security

Artifact and external-reference metadata are now recursively redacted in RunManifest
projections using the existing sensitive-key policy.

Durable stored metadata remains unchanged.

## Deterministic lineage

Task lineage now explicitly sorts:

~~~text
attempts
artifacts
external references
~~~

rather than relying on MetadataStore return order.

## M47 integration

External Workload Contract v1 now validates provider names, URI portability, metadata
portability and produced ArtifactReference values through the M48 contract.

## Persistence

No new Alembic revision is introduced.

The migration head remains:

~~~text
0003_retry_eligible_at
~~~
