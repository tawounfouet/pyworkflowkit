# PyWorkflowKit 0.8.0

Stable ecosystem interoperability release.

## Summary

0.8.0 promotes the M47-M52 interoperability line after transverse qualification of the
complete installed ecosystem boundary.

The release proves that PyWorkflowKit can remain a small embedded workflow runtime while
supporting independently packaged workloads, executors, metadata adapters, observability
sinks and external control planes.

## Transverse scenarios

The stable gate exercises, in one installed environment:

~~~text
A. core-only local workflow
B. third-party executor plugin
C. real PyIngestKit specialized workload
D. optional event/observability adapter
E. public control-plane provider
F. deliberately broken optional plugin isolated from core
~~~

## Qualification finding resolved before stable

The 0.8.0b1 ecosystem conformance helper initially over-constrained
`PluginType.WORKLOAD` by assuming every workload plugin factory directly produced an
`ExternalWorkload`.

Transverse qualification showed that this was too narrow for the canonical M50
PyIngestKit adapter package, whose plugin produces an adapter factory that then creates
the ExternalWorkload.

0.8.0 therefore preserves the intended layered contracts:

~~~text
PluginType.WORKLOAD
    generic plugin category

ExternalWorkload
    execution protocol for the workload ultimately composed into a task
~~~

Typed executor, metadata and event plugin instance validation remains unchanged.
