# PyWorkflowKit 1.1.0a2

## Developer Experience — DX02

PyWorkflowKit 1.1.0a2 adds a Rich presentation layer to the human-facing CLI while
preserving CLI Machine Contract v1 for automation.

This alpha introduces no workflow-runtime semantic change.

## Added

- direct runtime dependency on `rich>=13.8,<16`;
- internal `pyworkflowkit.cli_rendering` presentation package;
- Rich validation summary;
- Rich execution-plan tree;
- Rich run and persisted-run summaries;
- Rich event and plugin tables;
- Rich manifest summary;
- Rich doctor health/diagnostic presentation;
- Rich human error rendering on stderr;
- DX02 acceptance tests covering human and machine modes.

## Preserved

The machine-facing path remains unchanged:

```bash
pwk plan workflow.module:demo --json
```

The JSON keys, nested shapes, stdout/stderr behavior, and application-owned exit codes
remain governed by CLI Machine Contract v1.

`pwk version` remains plain single-line text.

## Architecture

```text
command
   ↓
stable payload
   ├── --json → JSON renderer
   └── human  → Rich renderer
```

Rich is presentation only. It does not enter the domain, application, persistence,
executor, plugin, or control-plane contracts.

## Compatibility

- `pwk` remains the canonical command;
- `pyworkflowkit` and `pyworkflow` remain compatible aliases;
- `pyworkflowkit.cli_rendering` is explicitly classified as internal;
- the frozen 1.0 public API remains unchanged.
