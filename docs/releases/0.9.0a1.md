# PyWorkflowKit 0.9.0a1

First 1.0 release-candidate stabilization alpha.

## Objective

0.9.0a1 starts **RQ-01 — Public API Freeze**. The release does not expand the workflow
runtime. It turns the already intentional public facades into an explicit, executable
compatibility contract on the path to 1.0.

## Added

- machine-readable `pyworkflowkit.public_api` contract;
- `PUBLIC_API_CONTRACT_VERSION = "1"`;
- explicit `PUBLIC_API_TARGET_RELEASE = "1.0.0"`;
- deterministic snapshots of the package-root, ecosystem, control-plane, integration,
  plugin, and public-api facades;
- acceptance coverage that rejects accidental additions, removals, duplicate exports,
  or missing exported attributes;
- dedicated CI and Release Qualification gates for the public API freeze.

## Frozen facades

```text
pyworkflowkit
pyworkflowkit.ecosystem
pyworkflowkit.control_plane
pyworkflowkit.integrations
pyworkflowkit.plugins
pyworkflowkit.public_api
```

Importable implementation modules such as `application`, `domain`, `adapters`, and
individual port implementations are **not** promoted to the 1.0 public facade by this
milestone.

## Compatibility policy

RQ-01 starts with no active removals:

```text
ACTIVE_DEPRECATIONS = ()
```

Any future change to a frozen facade during 0.9 must be explicit, reviewed, and handled
through the existing compatibility/deprecation policy.

## Artifact qualification

Release Qualification installs the built wheel and executes the RQ-01 acceptance test
against that installed artifact. Source-tree agreement alone is not sufficient.

## Scope control

0.9.0a1 adds no scheduler, worker fleet, broker, Web UI, IAM/RBAC, new executor model,
new recovery semantics, or new workflow feature.
