# PyWorkflowKit 0.9.0rc2

Second PyWorkflowKit 1.0 release candidate.

## Why RC2 exists

The first stable-promotion attempt from `0.9.0rc1` exposed a compatibility-contract
defect rather than a runtime defect.

Ecosystem SDK contract v1 still declared:

```text
minimum           = 0.8.0b1
maximum_exclusive = 1.0
series            = 0.8-0.9
```

and the reference/template integration packages used dependency ranges ending at:

```text
<1.0
```

That made the intended stable `1.0.0` runtime incompatible with its own ecosystem
qualification fixtures.

Under the RQ-06 promotion policy, the stable PR was closed instead of bypassing the
contract.

## Compatibility correction

RC2 changes the Ecosystem SDK v1 compatibility window to:

```text
minimum           = 0.8.0b1
maximum_exclusive = 2.0
series            = 0.8-1.x
SDK contract      = 1
```

This preserves the SDK contract version while extending the supported runtime line through
PyWorkflowKit 1.x.

Reference and qualification package dependency ceilings are aligned to `<2.0`.

## Scope

The correction changes compatibility metadata and qualification fixtures only.

It does not add:

```text
new workflow semantics
new executor behavior
new persistence behavior
new plugin protocol
new configuration semantics
new scheduler/platform capability
```

## Qualification

RC2 must rerun the complete RQ-06 corpus:

```text
RQ-01 Public API Freeze
RQ-02 Compatibility & Deprecation
RQ-03 Typing & Static Contracts
RQ-04 Developer Experience & Documentation
RQ-05 Packaging & Distribution
runtime tests
SQLite/PostgreSQL upgrade matrices
reference integrations
control-plane provider
ecosystem SDK
security
aggregate 1.0 release-candidate gate
final Release qualification gate
```

## Promotion rule

If RC2 qualifies without further functional or compatibility defects:

```text
0.9.0rc2
   ↓
same-qualified-code-version-metadata-only
   ↓
1.0.0
```

Any additional functional or compatibility correction requires another RC iteration.
